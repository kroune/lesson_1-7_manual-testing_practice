### API

Все запросы делал в API-лаборатории, режим normal, версия из ответов X-Lab-Version: workshop-1.0, X-Lab-Mode: normal.

1. `GET /applications` -> 200, массив из 3 заявок (после сброса), у всех полный набор полей. После UI-заявки Дарьи - 4

   name, topic, createdAt) - нарушение R8. `GET /applications/999` -> 404 NOT_FOUND - корректно.

   api

   поля email -> 400 INVALID_EMAIL; с именем из одного символа -> 400 INVALID_NAME. После каждого отказа повторный
   `GET /applications` - количество записей не меняется, мусорных записей нет.

## Решение о выпуске

К выпуску не готово. Проверил основной пользовательский сценарий (заполнение и отправка формы, список, черновик,
режимы стенда) и API отдельно (GET списка и по id, POST корректный и некорректный, контроль состояния после запросов).

отвечает 201 и теряет заявки с темой api (R7), GET /applications/3 отдаёт объект без email (R8), список дублируется при
обновлении (R1), форма стирает введённые данные при ошибке (R4) и отправляет POST с пустым именем (R2), "Удалить
черновик" не удаляет черновик из хранилища (R5), на 360 px есть горизонтальная прокрутка (R6). Первые два считаю
блокерами: это потеря пользовательских данных и нарушение контракта. Не проверено: режим delay, коды 405/409/413,
сохранение заявок при перезапуске сервера.
